## 〇、先泼三盆冷水

在开工之前，有三件事必须说清楚。第一件是反对你做这个决定的**理由**——决定是对的，但理由不牢靠，而理由不牢靠会让你在遇到困难时动摇。

### 冷水一：「AI 没泡沫」这个前提不成立，请换一个理由

**"AI 是否存在泡沫"是 2026 年公开争议最大的问题之一**，经济学家、投资人、从业者之间存在大量严肃分歧，双方都有扎实的论据。我没有做过系统性验证，不会替你下结论——但断言"几乎没泡沫"缺乏依据，这是需要你自己去判断的事。

好消息是：**你的决定不需要依赖这个前提。** 换一个更牢固的理由：

> **端侧推理能力依附于存量设备的增量升级，而不是某个 AI 应用能否爆发。**

支撑这个判断的是三个已经发生、不依赖预测的事实：
1. **存量规模**：全球 IoT 设备已超 300 亿台，其中约 **75% 的边缘数据在本地处理**。这个存量不会因 AI 寒冬消失。
2. **合规驱动**：数据主权法规（GDPR、欧盟 CRA、PSTI Act）在持续收紧。把原始音视频传上云，正从"默认做法"变成"需要设计规避的做法"。这是**合规成本驱动的刚性需求**，与 AI 热度无关。
3. **物理约束**：延迟、功耗、带宽三个约束永远存在。云端推理在自动驾驶、工业控制、可穿戴设备上无解。

**所以正确的说法是：边缘 AI 的抗泡沫性强于具身智能，因为它的需求分散在数百个行业和 300 亿台存量设备上，而不是押注"人形机器人能否落地"这一个赌注。** 这个理由比"AI 没泡沫"扎实得多，也更经得起未来的质疑。

### 冷水二：你的 F407VET6 在这条路线上基本派不上用场

这是转方向最实际的代价，必须说清楚：

| 规格 | STM32F407VET6 | 现代边缘 AI 主战场 |
| --- | --- | --- |
| 算力 | Cortex-M4 @168 MHz，仅 FPU | Cortex-A76 + NPU，**6–67 TOPS** |
| 内存 | 192 KB RAM | 4–32 GB LPDDR |
| 能跑什么 | Keyword Spotting、异常检测、IMU 分类 | YOLO 系列、1–8B 端侧 LLM、VLM |

**转边缘 AI = 必须买新硬件，预算 ¥800–2,800。** 这与具身智能不同——在具身智能路线里，F407 能做伺服关节，是核心部件；在这里它只能当入门教具。

我没有删掉它，而是把它放进**阶段 0 做 TinyML 地基**：零成本建立"训练 → 量化 → 部署 → 性能剖析"的完整认知闭环。这个闭环在 MCU 上只需 6 周就能跑完，在 Linux 平台上要 3 个月。

### 冷水三：10 个月只是起点，不是终点

500 小时能让你从零到"能在面试里讲清 trade-off 并展示作品集"。但阶段 3、4（算子与编译栈）的真正精通需要 1000+ 小时。这份路线图的目标是把你送到**能拿到第一份边缘 AI 岗位 offer** 的位置，不是送到专家位置。

## 一、结论：一个主干 + 两个卫星

主干仓库：**[ggml-org/llama.cpp](https://github.com/ggml-org/llama.cpp)**

| 项目 | Stars / Forks | 语言 | 最近提交 | 在本路线中的角色 |
| --- | --- | --- | --- | --- |
| **ggml-org/llama.cpp** | **126,525 / 22,544** | C++ | 2026-08-31 | **主干**（~60%）端侧 LLM 推理，算子与后端 |
| Tencent/ncnn | 23,769 / 4,494 | C++ | 2026-08-28 | 卫星（~20%）视觉推理，代码清晰易精读 |
| microsoft/onnxruntime | 21,684 / 4,191 | C++ | 2026-08-31 | 参考工业标准运行时 |
| alibaba/MNN | 16,003 / 2,423 | C++ | 2026-08-31 | 备选（国内就业认可度高） |
| **apache/tvm** | **13,710 / 3,962** | Python | 2026-08-31 | 卫星（~10%）编译栈，阶段 4 精读 |
| NVIDIA/TensorRT | 13,310 / 2,401 | C++ | 2026-08-25 | 平台绑定（Jetson 上必用） |
| openvinotoolkit/openvino | 10,773 / 3,344 | C++ | 2026-08-31 | 参考（Intel 平台） |
| pytorch/executorch | 4,973 / 1,131 | Python | 2026-08-31 | 关注方向（PyTorch 官方端侧方案） |
| google-ai-edge/LiteRT | 3,350 / 434 | C++ | 2026-08-31 | 阶段 0 用（TFLite Micro 后继） |

**为什么主干选 llama.cpp 而不是 TVM 或 ncnn：**

1. **代码可读性。** 核心 `ggml.c` 是单文件张量库，几万行但结构清晰，配 `gguf` 格式和 `llama.cpp` 主体，一个业余学习者能在 3 个月内读懂主干。TVM 的编译栈（Relay → TE → TIR → codegen）没有 6 个月啃不动。
2. **技能可迁移。** 量化算法、KV cache 管理、SIMD 算子、多后端抽象——这些在 Jetson、RK3588、手机、车机上全部通用，不绑定任何厂商。
3. **活跃度与贡献门槛。** 126K stars、22.5K forks，每天有提交。新后端、新算子、新量化方法的 PR 常年开放，贡献路径明确。
4. **与你已有积累同源。** INT4/INT8 量化、蒸馏、推理优化——你在 LLM 方向学的东西在这里直接复用，不需要重新建立认知。

**为什么不选 ncnn 当主干**：它很优秀、代码极清晰，但主要覆盖 CV 推理，深度不足以支撑到"精通"。放在阶段 2 作为视觉推理的实战对象最合适。

## 二、硬件选型

### 三个候选（价格为海外渠道参考，国内需自行核对）

| 平台 | 算力 | 参考价 | 优势 | 劣势 |
| --- | --- | --- | --- | --- |
| **Jetson Orin Nano Super** | **67 TOPS**（2024 年底由 40 升级） | $249–399 | CUDA + TensorRT 生态最成熟；YOLO11n @15W INT8 约 **270 FPS**；JD 中 TensorRT 出现频率远高于 RKNN | 贵；需主动散热；JetPack 是专属生态 |
| RK3588（Orange Pi 5 Plus 16GB / Radxa Rock 5B+） | 6 TOPS NPU | $130–229 | 性价比 2–3 倍；8 核、最高 32GB、M.2 NVMe、2.5GbE | RKNN 工具链成熟度低；Armbian 镜像需折腾 |
| 树莓派 5 + Hailo-8L/8 | 13 / 26 TOPS INT8 | Pi5 ~$64 + 加速模块 $70–200 | 社区最大、资料最多 | PCIe 带宽受限；LLM 性能远弱于 Jetson |

**我的建议：预算允许就直接上 Jetson Orin Nano Super。**

理由不是它最强，而是**对你这种 10–15 小时/周的业余学习者，时间比钱稀缺**。RK3588 省下的 ¥1,000–1,500，大概率会以 30–50 小时的额外环境折腾时间偿还——而 50 小时相当于你一个月的学习量。此外 JD 里 TensorRT 的出现频率明显高于 RKNN，就业对口性也更好。

**一个必须知道的坑：TOPS 数字不能跨架构比较。** 6 TOPS 的 RK3588 NPU 和 67 TOPS 的 Ampere GPU，在内存带宽、支持的算子集、运行时开销上完全不同。选型时看真实 benchmark，不看规格表。

### 阶段 0 · TinyML 地基 —— 在 MCU 上跑完第一个完整闭环
**第 1–6 周，约 72 小时　仓库：`google-ai-edge/LiteRT` + CMSIS-NN　硬件：F407VET6，¥0**

目标：用你手上这块板子，在 6 周内跑完"训练 → 量化 → 部署 → 性能剖析"的完整闭环。这个闭环在 Linux 平台上要花 3 个月，在 MCU 上只要 6 周。

| 周次 | 内容 | 产出 |
| --- | --- | --- |
| 1–2 | 环境搭建、PyTorch 训练一个 4 关键词的 DS-CNN 模型 | 基线浮点模型，准确率 >95% |
| 3–4 | 量化：训练后量化（PTQ）到 INT8，量化感知训练（QAT）对比 | 量化前后精度/体积对比表 |
| 5 | 部署：转 TFLite → C 数组 → F407 固件，CMSIS-NN 加速 | 固件可在板端实时推理 |

## 四、风险与诚实 caveat

1. **薪资数据来源有限。** 边缘 AI 的薪资数字（30–55K / 资深 60–80 万）主要来自猎头样本与行业媒体转述，且海外样本（UK £45K–180K、US $100K–150K）与国内口径不可直接换算。**建议你自己在 BOSS 直聘/猎聘上搜"端侧推理""TensorRT""NPU 部署"，用真实 JD 校准预期。** 这个动作花 30 分钟，比看十份报告有用。

2. **岗位总量少于通用嵌入式。** 边缘 AI 是高溢价方向，但岗位绝对数量不如嵌入式 Linux 驱动。这意味着**跳槽选择面更窄**，需要接受这一点。缓解方式：把阶段 1 的 Linux BSP 能力做扎实，它同时是通用嵌入式岗的入场券。

3. **llama.cpp 迭代极快。** 126K stars、每天提交意味着 API 和 GGUF 格式都会变。学习时锁定一个 commit 做实验，不要追着 main 跑。

4. **TOPS 数字是营销陷阱。** 已在上文强调，再重复一次：跨架构比较 TOPS 没有意义，只看 benchmark。

5. **阶段 3、4 的门槛是真实的。** 手写 SIMD kernel 和读 TVM 编译栈，需要 C++、体系结构、编译原理三方面的底子。如果到阶段 2 结束时发现吃力，**停在阶段 2 并转向"部署工程"方向** 是完全合理的选择——那个层级同样有 30–45K 的岗位，只是天花板低一些。不要硬撑。

6. **第 6 周设一个 checkpoint。** 阶段 0 是零成本的，但也是最容易放弃的（TinyML 的调试反馈比较枯燥）。6 周后重新评估一次：如果这个闭环你跑得开心，继续；如果痛苦，说明你可能更适合上层应用而非底层优化。
