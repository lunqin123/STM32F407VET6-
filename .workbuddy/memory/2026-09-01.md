## 方向切换：具身智能 → 边缘 AI（用户最终决定）

**用户决定理由：「AI 爆火，未来也几乎没泡沫」。已指出该理由不成立并给出替代理由：**
- "AI 是否存在泡沫"是 2026 年公开争议最大的问题之一，断言"几乎没泡沫"缺乏依据（未做系统验证，不下结论）
- 更牢固的理由：**端侧推理依附存量设备升级，不依赖单一 AI 应用爆发**
  - 全球 IoT 设备 > 300 亿台，约 75% 边缘数据本地处理
  - 合规驱动刚性（GDPR / 欧盟 CRA / PSTI Act），与 AI 热度无关
  - 延迟/功耗/带宽三约束永远存在
- 结论：边缘 AI 抗泡沫性强于具身智能，因需求分散在数百行业 + 300 亿存量设备，而非押注"人形机器人能否落地"

**已告知用户的第二盆冷水：F407VET6 在边缘AI路线基本派不上用场**
- Cortex-M4 + 仅 FPU + 192KB RAM → 只能跑 TinyML（KWS、异常检测、IMU 分类）
- 转边缘AI = 必须买新硬件 ¥800–2800；不像具身智能里 F407 能做伺服关节
- 处理方式：保留 F407 做阶段 0 的 TinyML 地基，6 周零成本跑完"训练→量化→部署→剖析"闭环

## 烧录（flash）能力补齐
- 给 `firmware/Makefile` 加 `flash` 目标：`openocd -f interface/stlink-v2.cfg -f target/stm32f4x.cfg -c "program build/firmware.elf verify reset exit"`（写 Flash + 校验 + 复位，脱离调试器独立运行）。
- `make -n flash` 空跑验证命令正确。实际烧录需 ST-Link V2 接 F407 的 SWD（SWCLK/SWDIO/GND/3.3V）且 BOOT0=0。
- 说明：F5 调试本身就是"编译+烧录+调试"一体；`make flash` 用于只想烧进去独立跑的场景。

## 结论：板子没有用户可编程 LED（用户最新疑问）
- 用户手上无外接 LED，板子只有 D1（电源灯常亮），按 F5 不闪灯。
- 已用 WATCH 确认 `GPIOC_ODR` 0→0x2000，证明固件 + 调试链路 100% 正常，PC13 确实被驱动。
- **结论**：D1 是电源指示（焊在 3.3V，固件控制不了）；多数 F407VET6 核心板/最小系统板本就没有用户 LED，因此"让板子自己的灯亮"在该硬件上做不到——不是程序 bug。
- 处置：`main.c` 保持多引脚版（PC13/PA6/PD12-15）并加注释，指明无需 LED 时用万用表直流档点这些排针看 ~0/3.3V 跳变即可反向验证；同时把 delay 调到 4000000（≈2.5s 半周期）便于读数。
