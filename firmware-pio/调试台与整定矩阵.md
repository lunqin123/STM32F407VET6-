> 配套工具：`tools/serial_bench.py`　｜　配套固件：`src/closedloop.cpp`（含遥测 `O` 命令）
> 目的：把"调参靠手感"变成"调参靠数据"。**每个结论都要有 CSV 和指标表支撑**，因为面试要的是数字。

## 一、上机流程（严格按顺序）

| 步 | 动作 | 注意 |
|---|---|---|
| 1 | **关掉 12V 电源输出**，再烧录 | ★ 铁律：带电烧录必失败——PWM 开关噪声毁 SWD（报 Failed to write memory / verify 随机错位），已实测 |
| 2 | `pio run -e closedloop -t upload` | 若报 `SHFileOperationW 0x2`：`rm -rf .pio/build/closedloop` 后重试 |
| 3 | 插 USB（板载 USB 口，PA11/PA12），按一下 RESET，**先跑 `check`**（此步**不需要 12V**） | 上电诊断会直接告诉你编码器在不在读数。角度异常时**第一步永远是它** |
| 4 | **再**接通 12V，限流先设 0.5A，按一次 RESET | 上电自动做 FOC 对齐（电机会轻动一下）；**对齐成功角度读数才正常** |
| 5 | 跑测试台（会自动开遥测、结束时自动 `O0` 关掉） | 见下节 |

> 遥测默认关闭是**故意设计**：USB CDC 写阻塞会拖慢控制环，和"OLED 全帧刷新导致顿挫"是同一类问题。

> `--port` 可以省略，工具会等新 COM 口出现。

**产物**：`tools/runs/<时间戳>_<测试>.csv` + `.svg`（自绘，零依赖，浏览器可直接打开）。

**时间轴精度的关键设计**：阶跃时刻由**遥测里的 `target` 字段变化**判定（设备侧），不是主机发送时刻 —— 因此不受 USB 传输延迟影响，时间分辨率 = 遥测周期（默认 20 ms）。

**诚实提醒**：开着遥测测出来的指标，会比不开遥测**略差**（格式化 + USB 写入占了主循环时间）。这是测量本身的代价；所有实验都在同一遥测周期下做，所以**横向可比**。

### 度量纪律（2026-09-12 实测踩到）
**不要用相邻遥测样本差分去算"瞬时角速度"。** 两个原因会把它系统性放大：
1. **量化**：AS5600 是 12 bit，1 LSB = 0.088°；静止时角度就在 ±1 LSB 之间跳；
2. **间隔抖动**：遥测周期名义 20 ms，实测会在 5~12 ms 间抖。

实测后果：标称 `velocity_limit=10 rad/s` 的系统，差分出来的"峰值速度"是 **37.7 rad/s** —— 纯属伪影。

**可信的数据只有两类**：
- **角度轨迹本身**（`angle_deg` / `raw_rad` 列）—— 它是编码器真值，能做趋势判断；
- **固件侧指标**（上升 / 超调 / 调节 / 稳态误差 / 纹波）—— 由 `serial_bench.py` 的 `analyze_step` 算，定义明确。

**另一个陷阱**：**标准"超调"指标会漏掉过程振荡**。它只在目标**上方**找最大值；如果系统在目标下方来回摆，超调会显示得很漂亮。**判据：一定要看角度轨迹列，不要只看指标表。**

**静止时的量化极限环是正常的**（角度在 ±1 LSB 间以 ~50 Hz 交替、`vel` 同步翻符号），靠 `F`（速度 LPF）抑制，不是故障。

## 三、整定实验矩阵

**方法学：一次只改一个参数（OFAT）。** 改两个以上，出问题无法归因——这是排障的基本纪律，也是面试要讲的。

**基线（固件默认值，未特别说明则保持不动）**：

| 参数 | 命令 | 默认 | 含义 |
|---|---|---|---|
| 电压上限 | `L` | 2.0 V | 起步值，防过流 |
| 速度低通 | `F` | 0.03 | `motor.LPF_velocity.Tf`，低速量化噪声主滤波器 |
| 速度环 P | `P` | 0.2 | |
| 速度环 I | `I` | 20 | |
| 位置环 P | `A` | 20 | `motor.P_angle.P` |
| 速度上限 | `V` | 10 rad/s | 位置环内层速度环的给定上限 |

---

### E1 · 电压上限 `L`（先做，它决定后面实验有没有意义）

| L | 观察点 |
|---|---|
| 2.0 / 3.0 / 4.0 / 6.0 V（**限流 0.5A 起，逐步放开**） | `step 90°` 的稳态误差、调节时间、电机温升 |

**判据**：稳态误差 > 1° 说明**被限幅了**（带不动），此时调 PID 毫无意义——先解决电压。选"能到位、超调可接受、连跑 1 分钟不发烫"的最小 L。
**★ 选定后固定不动**，E2~E5 全部在它之下做，否则实验结果不可比。

```bash
$PY tools/serial_bench.py step --target-deg 90 --limit 2
$PY tools/serial_bench.py step --target-deg 90 --limit 3
```

---

### E2 · 速度低通 `F`（**这就是你 F 0.05→0.1 的定稿方法**）

**原理**：AS5600 是 12 bit，单圈 4096 计数 → **0.088°/LSB**。用差分求速度时，1 个 LSB 的量化误差会被采样周期放大，低速时速度信号被量化噪声主导。`Tf` 低通压掉噪声，但引入相位滞后。所以 **F 不是"越大越稳"，而是存在一个拐点**。

**症状对照表**：

| F | 现象 |
|---|---|
| 太小（0.005~0.02） | 速度信号毛刺大 → 电压/电流抖动 → 可闻"嗡嗡"、电机发热 |
| **合适** | 纹波明显下降，**而调节时间基本不变** ← 这个"而"就是拐点判据 |
| 太大（>0.15） | 相位滞后 → 超调增大，严重时低频振荡 |

**实验序列**：`F ∈ {0.01, 0.02, 0.03, 0.05, 0.08, 0.10, 0.15}`，每个 F 跑 **hold + velstep** 各一次。

**判据（双指标择点，别凭感觉）**：
1. 用 `hold` 找**纹波拐点**：纹波 RMS 开始明显下降的那个 F；
2. 再用 `velstep` 确认该 F 下调节时间**没有恶化超过 20%**；
3. 取两个字条件都满足的**最小 F**。

```bash
# Git Bash；PowerShell 用户把 for 换成：0.01,0.02,0.03,0.05,0.08,0.10,0.15 | ForEach-Object { ... }
for f in 0.01 0.02 0.03 0.05 0.08 0.10 0.15; do
  "$PY" tools/serial_bench.py hold    --speed 3.0 --record 8 --set F$f
  "$PY" tools/serial_bench.py velstep --speed 3.0 --set F$f
done
```
> 把 7 组"纹波 RMS / 调节时间"画成两条曲线，交点就是答案——**这个图本身就是极好的面试素材**。

---

### E3 · 速度环 `P`

固定：`I=20`、`F=` E2 定稿值。
扫描：`P ∈ {0.05, 0.1, 0.2, 0.3, 0.5, 0.8}`

| 现象 | 含义 |
|---|---|
| 响应慢、要靠 I 才补得上 | P 太小 |
| 超调大、来回摆、有持续振荡 | P 太大 |
| 低速下噪声被放大 | P 太大（**回 `hold` 复查纹波**，这一步很多人会漏） |

**判据**：`velstep` 超调 < 10%，且调节时间最小，且 `hold` 纹波未恶化。

---

### E4 · 速度环 `I`

固定：`P=` E3 定稿、`F=` E2。
扫描：`I ∈ {5, 10, 20, 40, 80}`

| 现象 | 含义 |
|---|---|
| 稳态速度略低于目标（有残差） | I 太小 |
| 阶跃后过冲、低频摆动、积分饱和 | I 太大 |

**判据**：`velstep` 的稳态误差 → 接近 0，且超调不增加。

---

### E5 · 位置环 `A` 与速度上限 `V`

固定：E2~E4 全部定稿。
扫描 A：`A ∈ {5, 10, 20, 40, 60}`（`V=10`）
扫描 V：`V ∈ {3, 5, 10, 20}`（`A=` 定稿值）

| 现象 | 含义 |
|---|---|
| 到位慢、有残余角度误差 | A 太小 |
| 位置超调、围绕目标来回摆 | A 太大 |
| 调节时间被"最长用时"卡住 | `V` 限得太死（位置环内层速度环给不上去） |

**判据**：`step 90°` 稳态误差 < 1°、超调 < 10%、无持续摆动。
> `V` 扫描能得到一条很漂亮的"**速度上限 vs 调节时间**"关系，直接对应"位置环斜率约束"的设计问题。

### E6 · 定稿验收：可复现性

```bash
$PY tools/serial_bench.py repro --test step --target-deg 90 --repeat 10
```
**判据**：调节时间离散度 **CV < 15%**。
CV 偏大先别调参 —— **先查机械是否松动、接线是否虚接**。这是"先证伪硬件，再怀疑算法"的纪律。

## 五、调到什么程度就停（三档验收）

停止标准由"**面试能不能讲透**"决定，不由指标漂亮程度决定。

**L1 及格**（能写进简历不被问穿）
- 位置稳态误差 < 1°；阶跃超调 < 10%；调节时间有具体数字
- 速度环稳态波动有具体数字
- 同命令 10 次可复现（CV < 15%）

**L2 目标线 —— 拿到即停**（只选一个深度点）
- **方案 A**：电流环闭环 + 带宽实测（≥1 kHz）+ 电流跟踪误差
- **方案 B**：无感观测器 + **用 AS5600 当"真值"**验估算误差
- 外加一条完整叙事（症状→假设→证伪→根因→对策→数字）+ 抗扰测试（突加负载 / 堵转 / 限流触发）

**L3 加分**（有余力才碰）：参数自辨识（R/L 对比万用表）、扫频出波特图给带宽与相位裕度、效率/温升曲线。

**停止信号（触任一条即停）**
1. 每个数字都能说出"从哪来"；
2. 某项卡住超过一个周末 → 降目标，**把"卡住的过程"本身写成面试故事**（比漂亮数字值钱）；
3. 开始为了好看而挑波形 → 停。**最烂的那个波形 + 定位过程最加分。**

## 八、故障处置：角度恒为 0（已实测确诊）

**症状**：遥测里 `angle` 恒等于 `0.000000`（速度也恒 0），OLED 显示 `Ang 0.0 deg`。

**根因链（不是"编码器坏了"，别乱换件）**：
```
12V 未通电（或电机没被拉到位）
  → initFOC() 里的 alignSensor() 测不到转动（moved < MIN_ANGLE_DETECT_MOVEMENT）
  → 返回 0，sensor_direction 保持 UNKNOWN(=0)
  → shaftAngle() = 0 × sensor->getAngle() = 0   ← 恒 0 的真正来源
  → 且 initFOC() 在失败分支调了 disable() → driver enabled = 0，电机之后也不会转
```

**关键洞察**：`shaft_angle` 恒 0 与"编码器损坏"**症状完全一样**，光看它无法区分。所以固件把
**编码器原始角 `raw`**（不乘 `sensor_direction`）单独作为遥测第 7 段暴露出来 —— 这是唯一能
独立验证编码器的字段。

**三步定位（用 `Z` 体检快照 / `check`）**：

| 看什么 | 结论 | 对策 |
|---|---|---|
| I2C 扫描里有 **0x36** | AS5600 在总线上，接线 OK | 继续看下一行 |
| **raw 非 0 或手转轴时变化** | 编码器在读数，硬件没问题 | 问题在**对齐**，不是编码器 |
| `motor_status = 0xE`、`enabled = 0` | 对齐失败、驱动被关 | **接 12V → 按 RESET** 重新对齐 |

**实测记录（2026-09-12）**：`raw = 5.4778 rad`、`I2C: 0x36 0x3C`、`status=0xE`、`enabled=0`
→ 编码器完好，唯一缺的就是对齐所需的动力。**结论：通电+RESET 即解决。**

**若通电后仍失败**，按序排查：
1. `L` 限压是否太低（2.0V 太小带不动转子）→ 临时 `L4` 再 RESET 一次；
2. 相序接错（U/V/W 与驱动板 PWM A/B/C 不对应）→ 换个顺序试；
3. 磁铁偏心/间隙过大 → 装正磁铁；
4. 若 `raw` 在手转轴时也完全不动 → 才回到硬件（磁铁/线/器件）。

**这条排障链本身就是面试素材**：症状（角度恒 0）→ 假设（编码器坏？）→ 证伪（raw 非 0、
I2C 有 0x36）→ 根因（对齐失败×方向 0）→ 对策（通电 RESET）→ 沉淀（把 raw 加进遥测）。

## 九、首次整定实测（2026-09-12 ｜ 定子已固定 ｜ 12V ｜ 限压 2V）

### 9.1 结论先行
**① 固件默认增益在「定子固定」的正确机械条件下是不稳定的**：位置阶跃出现 **~20 Hz、±21° 的持续振荡**（纹波 pp 43°）。而 **`A`（位置环）不是杠杆** —— 它在速度模式下根本不参与（我先调错了两轮才发现）。
**② 真正的杠杆是速度环积分增益 `I`：`I=20` 不稳，`I=10` 完全稳定**，纹波降到 **0.17° = 2 LSB 量化地板**。

### 9.2 F × I 二维扫描（90° 阶跃；P=0.2, A=20, V=10, 2V）

| F | I | 上升 ms | 超调 % | 调节 ms | 稳态误差 ° | 纹波 pp ° | 判定 |
|---|---|---|---|---|---|---|---|
| 0.03 | 20 | 451 | 25.5 | 3994 | −1.07 | **43.50** | ✗ 不稳（默认） |
| 0.05 | 20 | 340 | 35.4 | 4029 | −2.41 | **58.89** | ✗ 不稳 |
| 0.03 | 5 | 778 | 0.6 | 1400 | −0.19 | 0.178 | ✓ |
| 0.05 | 5 | 848 | 5.4 | 1737 | +0.02 | 0.178 | ✓ |
| 0.03 | 2 | 903 | 5.6 | 3994 | +2.71 | 10.99 | ✗ 欠增益（静差大） |
| **0.03** | **10** | **777** | **0.1** | **1370** | **−0.029** | **0.172** | ✓✓ 最优 |

**读法**：`I` 决定**稳定与否**（20 → 43°；10/5 → 0.17°）；`F` 只做**微调**（同一 I 下影响超调与调节时间，不改变稳定性）。I 太小则稳态误差变大（速度环低频增益不足）。

### 9.3 P 扫描（F=0.03, I=10）

| P | 上升 ms | 超调 % | 调节 ms | 稳态误差 ° | 纹波 pp ° | 判定 |
|---|---|---|---|---|---|---|
| 0.2 | 777 | 0.1 | 1370 | −0.029 | 0.172 | ✓ |
| **0.5** | 802 | **0.0** | **1194** | +0.066 | 0.264 | ✓ 调节最快 |
| 1.0 | 607 | 13.7 | 4004 | −1.46 | 16.26 | ✗ 不稳 |
| 2.0 | 550 | 17.5 | 3994 | −2.53 | 22.50 | ✗ 不稳 |

### 9.4 推荐定稿
`L=2V, F=0.03, P=0.5, I=10, A=20, V=10` → 90° 阶跃：**超调 0.0%、调节 1194 ms、稳态误差 +0.066°、纹波 0.26°**
（要最低纹波则取 `P=0.2` → 0.172°）

> ⚠️ **本节结论已被 §十一 推翻（2026-09-12 晚）**：上面的数字是**单次测量**。
> 事后用 `tools/screen_step.py` 复测证明：`A=20` 在本机是**持续振荡点**
> （90° 阶跃每次振 15~22°、~19 Hz），这里的"干净"只是**双稳态里侥幸抽到的那一次**。
> 连 `V=10` 也是失稳配置。**现行定稿见 §11.5：`L=2V V=3 P0.5 I10 F0.05 A10`。**

> 上升/调节时间在 0.7~1.2 s 量级，比"定子未固定"时测得的 160 ms **慢得多** —— 后者是假象，见 9.5①。

### 9.5 两条硬教训（比数字值钱）

**① 机械边界条件是调参的前置条件。**
定子未固定时测出的"超调 0.1%、上升 160 ms"是**假象**：定子跟着反扭，把振荡吸收掉了。固定后同一套参数立刻露出 43° 持续振荡。
→ **动 PID 之前先问三句：定子固定了吗？轴自由吗？有没有负载？** 被控对象不对，参数毫无意义。
（对照：稳态指标在两种情况下都可信，因为静止时没有反作用力矩 —— "稳态可信、瞬态不可信"这个区分要记住。）

**② 测试序列不能污染初始条件。**
`hold` 会让电机转到第 N 圈；紧接着跑 `step` 若用**绝对角 0** 当起点，电机会一路倒转几十圈，而 `--settle` 完全来不及 → 采到的"基线"其实是电机在狂奔，会被误判成**失控/极限环**（实测踩过：角度跑到 6515°~9393°，即第 26 圈）。
→ `serial_bench.py` 已修复：**阶跃改为「以当前位置为起点」的相对阶跃**，从此免疫累计角；`--start-deg` 已作废（保留参数但忽略）。

### 9.6 ★ 工具安全设计：退出时必须把电机留在稳定状态

- **事故（2026-09-12 18:32）**：会话结束时把失稳增益 `P=2.0` 留在了固件 **RAM** 里 → 电机随后**持续剧烈振荡**，只能靠远程复位（`STM32_Programmer_CLI -c port=SWD -rst`）救回。
- **根因**：`serial_bench.py` 用 `--set` 改的是固件 RAM，**退出时不会自动还原**；而"关遥测"解决不了增益问题。
- **修复**：新增 `SAFE_PARK = ["P0.5", "I10", "F0.03"]`，**任何退出路径（正常 / Ctrl-C）都先恢复它，再发 `O0`**，并在终端打印确认。
- **★ 二次修复（同日更晚，教训更贵）**：该名单**漏了 `A`（位置环 P）** —— 而 A 同样是稳定性参数。
  后果是**整轮参数扫描被污染**：`screen_step` 依次跑 `-` → `V2` → `A8` → `I5` → `F0.06` 时，
  `A8` 之后 A 一直是 8 且从未还原，于是 `I5` / `F0.06` 两组的"干净"**其实全是 A=8 带来的**，
  与 I / F 无关。差一点据这组**假结论**去写固件默认值。
  现为 `SAFE_PARK = ["P0.5", "I10", "F0.05", "V3", "L2", "A10"]`。
  → **铁律一：凡是能改到电机动态的参数，都必须列入 `SAFE_PARK`。**
  → **铁律二：做配置扫描时，每组的差异参数必须在 `--cfg` 里显式写出**，绝不能依赖"上一组留在 RAM 里的状态"。
- **通用原则**：凡"会改设备参数"的测试工具，**退出必须回到已知安全态**。否则一次实验事故会以"设备自己坏了"的形式在事后才暴露，排查成本极高。

### 9.7 复现性预警（**E6 必须先做**）

同参数（`P0.5 I10 F0.03`，2V）两次 90° 阶跃：

| 次序 | 上升 ms | 超调 % | 调节 ms | 稳态误差 ° | 纹波 pp ° |
|---|---|---|---|---|---|
| 第一次 | 802 | 0.0 | 1194 | +0.066 | 0.264 |
| 复位后 | **125** | **8.5** | 1686 | **+0.0000** | **0.0000** |

**稳态指标极其一致**（都在 0.0x° / 量化地板），**但瞬态指标差了 6 倍**（上升 125 vs 802 ms）。

可能来源：复位后重新对齐（`zero_electric_angle` 变化）、起始位置不同导致的静摩擦/预紧差异、机械装配状态变化。

→ **结论：跑完 E6（10 次重复、CV<15%）之前，不要对外引用任何瞬态数字**（上升/超调/调节）。**稳态数字（稳态误差、纹波）可以引用。**

> ⚠️ **升级版预警（详见 §11.1）**：本机不止"两次不一致"，而是**双稳态** ——
> 同一组参数会在「干净衰减」与「自持 ~19 Hz 极限环」之间跳。
> 所以**单次跑得漂亮 = 侥幸**，判断一个工作点必须看 **N 次重复的 min/max**。
> 工具已备好：`tools/screen_step.py`（多组参数各跑 N 次，输出紧凑对比表）。

## 十、母线电压：可用窗口与过压风险（DRV8313 口径，已核手册）

> 触发：问"如果电压输入很大会怎么样"。本机电源是**带限流(CC)的可调直流电源 3–24 V / 0–5 A**，"把电压拧大"是真会发生的操作，不是假想场景。

### 10.1 先记住两句话

1. **母线电压 ≠ 加到电机上的电压。** 真正决定电机电流的是 `motor.voltage_limit`（本机 **2 V**），母线只是"上限的上限"。所以**升母线不会自动让电机变强** —— 除非你还动了别的。
2. **驱动芯片没有过压保护（OVP）。** DRV8313 的保护只有 OCP / 短路 / UVLO / 过温(TSD)。**超过绝对最大额定就是直接永久损坏，没有任何东西拦你**。唯一能兜底的是电源自己的**限流(CC)** 和你自己的手。

### 10.2 电压窗口（TI SLVSBA5D 手册值）

| 区间 | 含义 | 依据 |
|---|---|---|
| **< 6.3 V** | 驱动不保证启动（UVLO 未释放） | UVLO：VM 上升沿 6.3–8 V |
| **8 – 12 V** | ★ 推荐工作区（本机 12 V） | Rec. operating VM = 8–60 V |
| **12 – 30 V** | 可运行，但**必须同步改 `voltage_power_supply`**，且电机热风险随 V² 增长 | 板级口径 12–30 V（MKS V3.2） |
| **30 – 60 V** | 超出板级口径：板载电解电容耐压、板载线性稳压器功耗先扛不住 | **板 ≠ 芯片** |
| **60 – 65 V** | 芯片额定上限区，零余量 | ABS MAX VM = 65 V |
| **> 65 V** | **永久损坏** | ABS MAX（"stresses beyond… may cause permanent damage"） |

### 10.3 三条"抬压"会咬人的路径

**① 软件量纲错配（最阴的一条）。**
SimpleFOC 把"电压设定值"换算成占空比时要除以 `voltage_power_supply`：
`duty = U / voltage_power_supply`，实际加到电机上的是 `duty × 真实母线电压`。
→ 若只把电源拧到 24 V、而固件里 `voltage_power_supply` 还是 **12.0**，实际输出电压会**静默翻倍**（2 V → 4 V），代码和遥测都看不出来。
→ **铁律：母线电压与 `voltage_power_supply` 必须同步改，改完重跑一次硬件体检（`check`）。**

**② 热 —— 最先咬到的是电机，不是驱动板。**
云台电机相电阻 21.2 Ω，绕组电流 ≈ `voltage_limit / 21.2`，铜损 ∝ **V²**（`P ≈ 1.5·V²/R`）：

| `voltage_limit` | 相电流（幅值） | 定子铜损 |
|---|---|---|
| 2 V（当前） | 0.09 A | 0.28 W |
| 6 V | 0.28 A | 2.5 W |
| 12 V | 0.57 A | **10.2 W** |
| 24 V | 1.13 A | **40.8 W** |

24 V 下 1.13 A **仍在 DRV8313 的 2.5 A 峰值能力之内** → **驱动板没事，电机先烧**。2208 云台电机是几十克的小铝坨，40 W 塞进去是几十秒的事。
→ 这就是云台电机必须用**低 `voltage_limit`**（2–4 V）跑、而不是"母线多大就用多大"的根本原因。

**③ 回馈（regen）把母线往上顶。**
高速 / 急减速时电机变发电机，能量倒灌回母线；而本机电源是"只能源、不能吸"的类型 → 母线电压被抬起来。母线越高，能被抬到的绝对电压越高。再叠加**热插拔/上电瞬间**的 LC 振铃尖峰，即使标称 24 V 也可能瞬时越界。
→ 缓解：别用远超需求的母线；电源侧加大电解电容；限制减速度；有条件加泄放电阻 / TVS。

### 10.4 谁先死（24 V 母线且 `voltage_limit` 也放到 24 V 的最坏情况）

1. **电机定子绕组** —— 40 W 铜损，最先冒烟（几十秒 ~ 几分钟）
2. **板载线性稳压器（LM7808）/ 电解电容** —— 若母线真的上到 30 V+
3. **DRV8313** —— 只有 > 65 V、或热插拔尖峰越界、或长期过热反复触发 TSD(150–180 °C)
4. 只要 `voltage_limit` 仍卡在 2 V，第 2、3 条都不会发生 —— **低限压才是真正的安全阀**

### 10.5 实操规则（写死）

- 母线**固定 12 V**，`voltage_power_supply` 就写 **12.0** —— 两个数字永远一致
- 用**限流(CC)** 当第一道保护：12 V 起步设 **CC ≈ 0.3–0.5 A**（额定约 0.57 A，留余量）
- 想"让电机更有劲" → 调 `motor.voltage_limit`（2 → 2.5 → 3 V，边调边摸温度），**不要去拧电源**
- 母线一旦要改：先**把限流拧到最小** → 断电改线 → 改 `voltage_power_supply` → 再上电跑体检

## 十一、~19 Hz 自持极限环：定位过程与定稿（2026-09-12 晚 ｜ E6 复现测试）

> 触发：按 §9.4"定稿"参数（`I10 F0.03 A20 V3 L2`）跑 **E6 复现验收**，结果 **10 次里 9 次不收敛**。
> 本节记录"为什么 §9.4 是错的、真凶是谁、怎么定位、现在的定稿是什么"。

### 11.1 现象：不是"偶发不一致"，是双稳态

- E6（`repro`，10×90° 阶跃）结果：**10/10 有效但 9/10 在振** ——
  调节时间全部打满 4 s 采集窗、超调 10~13%、**稳态纹波 17~23°**。
- 抓单次波形细看（角度/速度/raw 三个字段一致，排除编码器与遥测问题）：
  | 量 | 实测 |
  |---|---|
  | 稳态角度 | 目标附近 **±9.6°** 摆动（峰峰 **19.25°**） |
  | 振荡频率 | **≈18.85 Hz** |
  | 实测速度 | 峰峰 **10.7 rad/s**、峰值 **5.7 rad/s**（**远超速度上限 V=3**） |
  | 衰减 | **不衰减（自持）** → 判定 **极限环（limit cycle）** |
- 用 `screen_step.py` 以 **4 次/组、6 次/组**复测：`A=20` **四跑四振、六跑六振** ——
  所以它不是"偶发"，而是该参数下的**确定行为**；真正偶发的是 §9.4 那一次"干净"。

### 11.2 定位：控制实验把范围收窄到位置环

| 实验 | 现象 | 推论 |
|---|---|---|
| 速度模式 `hold 3 rad/s` | 角度**单调匀速**（7969°→8313°，正好 3.0 rad/s），**无机械振荡** | 电机 + 机械本体没有振 |
| 同上，只看**速度读数** | 抖动 ±0.5 rad/s RMS | 是**测量噪声**：12bit 编码器(0.088°)被微分放大，**不是机械抖动** |
| 位置模式阶跃（A=20） | **±9.6° 真实机械振荡** | 只有**位置环闭合成环**后才出现 → **位置环是激发源** |

→ 关键区分：**速度读数的抖动 = 测量噪声；位置模式的 19 Hz 摆动 = 真实机械振荡**。二者别混。

### 11.3 两个"假阳性"（方法论坑，比参数值钱）

**① `SAFE_PARK` 漏 `A` → 污染整轮扫描**（详见 §9.6 的"二次修复"）。
扫描是**顺序执行**的：`I5` / `F0.06` 两组其实带着上一组遗留的 `A=8` 在跑，
所以"它们也稳"**与 I/F 无关**。差一点把这组假结论写进固件默认值。

**② L1 判据不测纹波 → 极限环反而被判"三项全过"。**
`A=20` 时上升/调节/超调三项**极其重复**（每次都振 ~20°、都 4 s 不收敛、超调都是 11%），
CV 很小 → 工具打印了 **"✓ 三项全过：瞬态数字可以对外引用（可以写进简历）"**。
**一台持续振荡的机器不可能有值得写进简历的瞬态数字。**
→ 已在 `serial_bench.py` 增设**纹波绝对判据**（`纹波峰峰 max ≤ 1°`），且**不能**用 CV 判
（极限环的纹波 CV 反而很小）；判据由"三项"升级为"四项"。

### 11.4 边界与裕量（每组 4~6 次复现，L=2V、V=3）

| 配置 | 纹波峰峰(最大) | 调节时间(均值) | 上升(均值) | 判定 |
|---|---|---|---|---|
| `A20`（§9.4 旧定稿） | **22.06°** | 3988 ms | 410 ms | ✗ 六跑六振 |
| `A16` | 21.53° | 3130 ms | 420 ms | ✗ 双稳态（有时 0.09°） |
| `A13` | 1.41° | 600 ms | 455 ms | ✓ |
| `A10`（F0.03） | 0.79° | 665 ms | 445 ms | ✓ |
| `A8`（F0.03） | 0.26° | 735 ms | 490 ms | ✓ |
| **`A10;F0.05`（选定）** | **0.17°** | 707 ms | 450 ms | ✓ |
| `A16;F0.06` | 0.09° | 607 ms | 397 ms | ✓ |
| `A20;F0.06` | 0.09° | 577 ms | 387 ms | ✓ |

**两个杠杆的实测边界：**
- **位置环增益 `A`**：边界在 **13~16** 之间（A16 双稳态、A13 稳）。**旧默认 20 在边界之外**。
- **速度反馈滤波 `F`**：A=20 时边界在 **0.03~0.06** 之间；`F≥0.06` 可**单独**把 A=20 救回来。

→ 两个旋钮都管用，说明机制是**"位置环把速度反馈里的噪声放大成自持极限环"**：
  降 A = 减小放大倍数；加 F = 直接削掉噪声源。

### 11.5 ★ 定稿配置（已写入固件默认值，复位后依然生效）

```
L = 2V    V = 3 rad/s    P_velocity = 0.5    I_velocity = 10
F = 0.05 (LPF Tf)        A_angle = 10
```
- 90° 阶跃实测（6 次复现全过）：**上升 ~450 ms ／ 超调 ~0.1% ／ 调节 ~707 ms ／ 纹波峰峰 ≤0.17°**
- **裕量**：A=10 对边界 13~16（≈2× 余量）；F=0.05 对边界 0.03。
- 落地位置：`firmware-pio/src/closedloop.cpp` 的"控制参数"段；工具侧 `serial_bench.py` 的 `SAFE_PARK` 已同步。

### 11.6 复盘：被推翻的旧假说（留着，别再犯）

| 旧假说 | 复测结果 |
|---|---|
| "真凶是**速度环饱和**：`P_vel × V > 限压`，所以要 `V ≤ 4`" | **伪**。A 仍为 20 时单独把 V 降到 2，**仍四跑三振**。V 不是主因 |
| "`V=3` 是定稿关键参数" | V 只决定 90° 阶跃的**斜率**（上升时间）。保留 3 是为响应速度，**不是"防饱和"** |
| "§9.4 那组（A=20）已稳定" | **伪**。单次侥幸；A=20 实为**持续振荡点** |

→ **元教训**：**本机在旧工作点附近是双稳态的，单次实验没有判别力。**
  今后**任何"稳定/不稳定"的结论，都必须由 ≥6 次重复的 min/max 支撑**（`screen_step.py`）。
  这条纪律本身就是最好的面试素材：*"我不相信单次漂亮的波形，所以我写了个筛选器去量化离散度。"*
